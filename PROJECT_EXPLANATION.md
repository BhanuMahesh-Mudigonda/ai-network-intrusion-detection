# AI-Powered Network Intrusion Detection — Complete Project Explanation

This document explains the **exact, authoritative implementation** of the AI Network Intrusion Detection System found in this repository. It maps directly to the python scripts (`api/main.py`, `api/model_service.py`, `models/train_models.py`, `validation_audit.py`) and the frontend dashboard (`app/index.html`, `app/app.js`).

---

## 1. PROJECT TITLE
**AI-Powered Network Intrusion Detection System (AI NID)**

## 2. WHAT PROBLEM ARE WE SOLVING?
Modern enterprise networks generate millions of network connections every second. Security Operations Center (SOC) teams cannot manually inspect every individual network connection. Traditional firewall rules only check basic port numbers and IP addresses, missing complex or novel cyber attacks. 

Our system automatically analyzes network-traffic behavior patterns and predicts whether a network connection is **BENIGN (normal)** or a **potential cyber attack** in real time, allowing security teams to respond faster.

---

## 3. WHAT IS NETWORK TRAFFIC?
Network traffic refers to data packets travelling across a computer network between client devices and servers (e.g., HTTP web browsing, TCP handshakes, SSH sessions, file transfers). In this project, individual packets are aggregated into **network flows** (defined by 5-tuple: source IP, source port, destination IP, destination port, protocol).

---

## 4. WHAT IS FRAUD/INTRUSION/ATTACK IN THIS PROJECT?
An intrusion or attack is any unauthorized or malicious network connection attempt intended to compromise system availability, data integrity, or confidentiality. 

In this project, attacks include **14 distinct cyber attack types**:
- **DDoS / DoS** (Hulk, GoldenEye, Slowloris, Slowhttptest) — Overwhelming servers with flood traffic.
- **PortScan** — Probing open ports to find vulnerabilities.
- **Bot** — Botnet command-and-control communication.
- **Infiltration** — Internal network compromise and payload delivery.
- **Web Attacks** (Brute Force, XSS, Sql Injection) — Exploiting web application vulnerabilities.
- **Brute Force** (FTP-Patator, SSH-Patator) — Dictionary password guessing.
- **Heartbleed** — Exploiting OpenSSL memory leaks.

---

## 5. WHAT DATASET ARE WE USING?
We use the benchmark **CIC-IDS2017 Dataset** (Canadian Institute for Cybersecurity). It contains real-world captured PCAP network flow telemetry generated in controlled environments featuring realistic background traffic and up-to-date cyber attack vectors.

---

## 6. WHAT DOES ONE ROW OF THE DATA REPRESENT?
One row in the dataset represents **one completed network flow session** (a bidirectional communication stream between a client and server) described by **78 numerical measurements/features** and labeled with its ground-truth class (`BENIGN` or an attack name).

---

## 7. WHAT ARE THE 78 FEATURES?
The 78 features represent mathematical measurements of the network flow. Rather than displaying raw obscure feature names, we group them into **7 simple functional categories**:

1. **Connection Information** — Flow duration, destination port, header length (`Destination Port`, `Flow Duration`).
2. **Packet Counts** — Total packets sent in forward and backward directions (`Total Fwd Packets`, `Total Backward Packets`).
3. **Packet Sizes** — Min, max, mean, and standard deviation of packet lengths (`Fwd Packet Length Max`, `Packet Length Mean`, `Average Packet Size`).
4. **Traffic Rates** — Flow throughput and packet transmission speed (`Flow Bytes/s`, `Flow Packets/s`).
5. **Timing Information** — Inter-arrival time between packets (`Flow IAT Mean`, `Fwd IAT Min`, `Bwd IAT Max`).
6. **TCP/Network Flags** — Counts of TCP control flags (`FIN Flag Count`, `SYN Flag Count`, `RST Flag Count`, `ACK Flag Count`, `PSH Flag Count`).
7. **Active / Idle Behavior** — Time periods when the connection was actively transmitting data vs. resting idle (`Active Mean`, `Idle Max`).

---

## 8. WHY DO WE NEED THESE FEATURES?
A single metric (like total packets) cannot distinguish between a large legitimate file download and a DDoS flood. Combining 78 diverse behavioral measurements allows machine learning algorithms to detect subtle multi-dimensional attack signatures that humans and static rules miss.

---

## 9. WHAT DATA CLEANING IS ACTUALLY IMPLEMENTED?
As implemented in `api/preprocessing.py` and `notebooks/02_data_preprocessing.py`:
1. **Handling Infinite Values**: Replacing `+inf` and `-inf` (generated by zero-division in rate calculations like `Flow Bytes/s`) with column max or `NaN`.
2. **Imputation**: Replacing missing `NaN` values with column medians.
3. **Duplicate Check**: Auditing identical flow records across train and test sets (`validation_audit.py`).
4. **StandardScaler Normalization**: Transforming feature ranges to zero mean and unit variance ($\mu=0, \sigma=1$) fitted exclusively on training data.

---

## 10. HOW IS THE DATA SPLIT?
The dataset is split using **Stratified 80/20 Train/Test Split** (`test_size=0.2`, `random_state=42`). Stratification ensures that rare attack categories (like Heartbleed or Infiltration) retain identical percentage distributions in both training and test sets.

---

## 11. WHAT MACHINE LEARNING MODELS ARE ACTUALLY USED?
In `models/train_models.py`, three baseline supervised classification models were trained and compared:
1. **Logistic Regression** (Linear baseline)
2. **Random Forest** (Ensemble tree baseline)
3. **XGBoost (Extreme Gradient Boosting)** (Gradient boosted decision tree ensemble)

---

## 12. WHY ARE MULTIPLE MODELS COMPARED?
Multiple models were compared to evaluate trade-offs between model complexity, inference latency, memory footprint, and multi-class classification accuracy across imbalanced attack classes.

---

## 13. WHICH MODEL IS ACTUALLY USED FOR FINAL PREDICTION?
**XGBoost (`XGBClassifier`)** is used for final production inference. It achieved the highest overall accuracy (`99.85%`) and macro F1-score while maintaining sub-10ms single-flow inference times.

---

## 14. HOW DOES THE MODEL LEARN?
During training, XGBoost constructs an ensemble of decision trees. Each subsequent tree iteratively corrects the classification errors of previous trees by calculating gradients of the multi-class log-loss objective function over the 78 input features.

---

## 15. HOW DOES A NEW NETWORK FLOW GET PREDICTED?
When new network flow data is submitted:
1. **Input Validation**: `Pydantic` schema (`NetworkFlowInput` in `api/schemas.py`) validates that all 78 float values exist and are non-null.
2. **Preprocessing**: The saved `StandardScaler` scales the 78 inputs using the exact parameters ($\mu, \sigma$) learned during training.
3. **Inference**: The `XGBClassifier` calculates class probabilities for all 15 classes.
4. **Threshold Check**: If highest probability $\ge$ Confidence Threshold (default 80%), the predicted class is confirmed; otherwise flagged for review.

---

## 16. WHAT DOES THE PREDICTION MEAN?
- **BENIGN**: Traffic matches normal network behavior. Safe connection.
- **ATTACK CATEGORY** (e.g. `DDoS`, `PortScan`): Traffic matches known cyber attack behavior. Action required.

---

## 17. WHAT DOES CONFIDENCE/PROBABILITY MEAN IN THIS IMPLEMENTATION?
Confidence represents the output probability distribution score from XGBoost's `predict_proba()` function for the winning class (range 0.0 to 1.0, formatted as 0% to 100%).

---

## 18. WHAT IS FASTAPI?
FastAPI is a high-performance Python web framework used to build modern, production-grade REST APIs with automatic OpenAPI documentation and asynchronous endpoint execution.

---

## 19. WHAT DOES FASTAPI ACTUALLY DO IN THIS PROJECT?
In `api/main.py`:
- Loads the trained XGBoost model bundle once on startup.
- Serves `POST /predict` for single flow classification.
- Serves `POST /predict/batch` for bulk CSV prediction.
- Serves `GET /health` and `GET /model-info` for system health monitoring.
- Serves the frontend web dashboard at `GET /dashboard/`.

---

## 20. WHAT DOES THE DASHBOARD ACTUALLY DO?
The web dashboard (`app/index.html`, `app/app.js`) provides an interactive interface to:
1. Explain the project purpose and 4-step workflow to non-technical users.
2. Execute live predictions using sample presets (BENIGN, DDoS, PortScan) or custom CSV uploads via real API calls to `/predict`.
3. Display real prediction results, confidence scores, and threat status clearly.
4. Render 3D network topology visualization reacting to threat detections.

## 22. WHAT VALIDATION / DATA-LEAKAGE CHECKS WERE ACTUALLY PERFORMED?
In `validation_audit.py`, a rigorous **10-Point Audit** was performed:
1. Checked zero train/test overlap.
2. Checked duplicate flow records across splits.
3. Verified `StandardScaler` was fitted ONLY on training data (`X_train`).
4. Evaluated distribution drift using Kolmogorov-Smirnov statistical tests.
5. Final Audit Verdict: `VALID WITH CAUTION` (high performance verified on CIC-IDS2017).

## 24. WHAT IS THE REAL-WORLD USE OF THIS PROJECT?
It serves as an automated first-line defense layer in Security Operations Centers (SOC). It continuously filters millions of network packet flows in real time, alerting analysts only when high-confidence attack vectors are detected.

---

## 25. WHAT ARE THE LIMITATIONS?
1. **Dataset-Bound**: Model predictions rely on patterns present in the CIC-IDS2017 dataset. Novel zero-day attacks with completely unseen patterns may be misclassified.
2. **Pre-extracted Features**: Requires an upstream packet parser to aggregate raw PCAPs into 78 statistical flow metrics before submission to `/predict`.
3. **Investigation Required**: Model predictions provide statistical confidence, not legal certainty; flagged attacks should be verified by a human analyst.
